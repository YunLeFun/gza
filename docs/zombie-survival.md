# 僵尸生存：局内成长、武器组合与骑行分工

**状态：后续设计草案，2026-10-13。** 本次只维护设计与路线图，不修改游戏、战斗规则、武器、存档或联机协议。经验、三选一升级、武器组合、十分钟生存流程和新敌人均待实现；本文中的数量与节奏是原型范围，不是已验证的平衡或性能结论。

## 设计目标与参考

参考《吸血鬼猎人》（Vampire Hunters）公开介绍中的第一人称射击、武器堆叠与局内升级，让玩家从普通骑手逐步形成有特点的战斗组合。参考来源见 [官方 Steam 介绍](https://store.steampowered.com/app/2206270/Vampire_Hunters/?l=schinese)。本文的任务流程、生活用品升级和骑行分工是 GZA 的设计提案。

玩家在广州街区骑电驴寻找物资，下车清路、救人，使用本局获得的升级形成不同打法，最后集合撤离。城市路口、停车位置、骑楼与建筑遮挡成为路线和战斗选择的一部分。场景与人物继续延续广州街坊、骑手和夸张街机反馈的方向。

核心循环为：

```text
骑行寻找物资 → 停车清路 → 获得经验 → 补给点三选一
      ↑                                  ↓
      └──── 转移到下一处任务点 ← 形成更强的武器组合
                                         ↓
                                  救人、集合并撤离
```

目标是让每次升级改变至少一种选择：优先清哪类敌人、使用哪件工具、如何站位、何时停车，以及谁留下支援。短局结束后可以换一套组合再试；升级不能让玩家跳过救援和撤离目标。

## 与现有僵尸突围的关系

[现有僵尸突围说明](city-zombie-coop.md)中的步行、双座电驴、枪械、生活用品近战、物资领取、救援与撤离是可复用基础。当前没有通用经验和局内升级系统，也没有本文的敌人组合或武器进化。

该方案作为城市「僵尸突围」活动的后续生存规则变体，与既有任务规则分别标识。进入同一广州城市场景，复用地图、输入、碰撞和战斗宿主；不要求新首页主模式或另一套城市加载。具体活动入口和规则选择 UI 在实现时确定，既有玩法与旧房间保持原有行为。

优先验证离线单人，再扩展 1–4 人合作。游戏中的感染故事和既有剧情进度继续独立管理；本局击杀、经验与装备不写回官方配送、购买权益、制服解锁或普通探索背包。

## 首个原型范围

| 项目 | 原型提案 |
| --- | --- |
| 场地 | 一处已开放且路网连通的广州街区，限定活动范围，复用现有地图 |
| 时间 | 约十分钟有效对局时间，包含转移与战斗；单人暂停及补给选择阶段不计时 |
| 玩家 | 先离线单人；合作规则在后续阶段验证 |
| 基础武器 | 冲锋枪、扫把、雨伞三种，复用现有武器与工具形象 |
| 装备容量 | 一件主枪械、一件可用近战工具；开局选择扫把或雨伞，首个原型不自动叠加两件近战 |
| 升级池 | 六种升级，目标在完整流程中提供五次选择机会 |
| 任务 | 取得物资、骑行转移、清路、救起一名幸存者、集合撤离 |
| 敌人 | 先普通感染者，再逐项验证冲刺型与精英型；远程型与更多组合后续扩展 |
| 终局 | 完成救援并撤离胜利；单人倒地或有效对局时间耗尽失败 |

原型不加入永久属性成长、无限模式、武器制作或自动车载攻击。采用有限敌人和有限触发次数，先观察玩家能否理解升级并主动使用组合。现有活跃敌人、场景和发布预算是约束，不能从参考游戏的敌人数或武器数直接推导本项目可以承受的规模。

## 局内节奏与任务目标

以下时间窗口是初始节奏目标，需要真实试玩调整。任务由实际交互完成，时间到点不会自动完成清路或救援。

| 有效对局时间 | 玩家目标 | 成长与压力 |
| --- | --- | --- |
| 0–2 分钟 | 获取物资，完成第一处小规模清路 | 学习枪械和近战，获得第一次升级机会 |
| 2–5 分钟 | 骑行至下一处任务点，停车处理包围 | 普通敌人配合少量冲刺型，形成第二、第三次升级机会 |
| 5–8 分钟 | 完成救援点战斗，下车救人 | 验证精英敌人与已形成的组合，提供后续两次升级机会 |
| 8–10 分钟 | 带幸存者抵达撤离区并集合 | 在有限追击压力下完成撤离，避免只在安全点持续刷怪 |

固定路线任务保证足够的最低经验，正常完成主要目标时能获得计划中的五次选择机会；原型不依赖额外绕路刷怪才能成长。经验超过上限不再产生新选择，后续仍推进任务和撤离。错过可选击杀可以影响取得升级的先后，但不造成必须无限刷怪才能继续的局面。

到达救援点前仍需完成指定骑行阶段。车坏或原车不可达时使用已有安全找车和下车规则；至少保留一条可行转移方案。救援完成后允许幸存者跟随步行，或占用停稳车辆的空后座；队友已占后座时需要调整座位与接应，不能挤入第三个乘员。

有效对局时钟由宿主管理，在单人暂停与补给选择阶段冻结；界面同时区分活动用时和现实经过时间。合作玩家打开个人菜单不会暂停房间。活动用时达到上限仍未撤离时明确失败并提供重试或返回街区，不把超时当作自动胜利。

## 局内经验与三选一升级

### 经验来源与归属

经验由宿主确认的敌人击倒、物资交接、清路与救援里程碑产生。每个敌人或任务事件有唯一身份，重复事件、网络重发、倒地恢复和重复交互不能再次发放经验。可拾取经验只放在可通行地面；无法形成安全落点时直接按规则计入，不能让升级依赖穿墙、涉水或卡住的掉落。

经验达到本局阈值后新增一次待选机会，战斗中的 HUD 提示“下个补给点可升级”，不会直接弹窗抢走移动或瞄准。多个机会按顺序排队，领取选择后立即由宿主确认效果；上下车保留本局等级与待选机会。

单人经验归本局玩家。合作阶段采用队伍共享经验进度，每次升级给每名当前队员一次个人选择；击杀数可以单独记录，但不会把升级机会全交给最后一击玩家。无论谁拾取经验，同一掉落只消费一次；某位队员倒地不应丢失已获得的待选机会。

### 选择时机与暂停行为

补给点需要停车、下车并完成当前清路，才能进入升级阶段。单人升级时冻结对局模拟与活动计时，保留选择界面操作；关闭或切到后台不会让自动武器继续攻击或拾取经验。

合作时，由权威端在当前行动成员均抵达、倒地成员已处理且阶段目标完成后开启全队补给阶段。冻结战斗、波次和任务计时，所有玩家分别选自己的升级；个人提前选完可以查看队友进度，但不能提前恢复战斗。全部确认后统一继续。选择阶段采用不随战斗冻结的倒计时，原型建议 15 秒；未操作时应用已展示的默认选项。暂停、超时和默认选项的具体流程需在合作阶段共同验收。

升级界面显示效果、适用武器、当前等级、上限和可能的组合，支持键鼠、触屏及手柄焦点。选择必须使用稳定选项 ID；重复确认只生效一次，旧阶段或过期选项被拒绝。涉及 UI 时复用 [共享组件与设计 token](ui-components.md)，保留输入释放与焦点恢复。

### 升级池与抽取规则

每次提供三个不同的合格选项，由固定种子和玩家专属抽取序列产生。只抽取已携带武器适用、前置条件满足且未达到上限的升级；首个原型不消耗货币重抽，也不允许客户端自报抽取结果。

若只有两个或一个合格选项，按实际数量展示，不补入不适用工具或已满级项目；没有合格选项时，将该次机会转换为一次有上限的本局生命／弹药补给，并说明原因。补给只恢复实际缺口，生命和弹药已满时直接消费机会并提示“装备与补给已满”，不能凭空增加最大值或留下无限待选队列。

抽取和选择以对局、玩家、升级序号与选项 ID 记录；重开重新生成本局，单人暂停不会重新抽取，网络重发不会改变选项。相同内容与种子可以用于重复试玩，但不承诺跨设备物理逐帧一致。

### 六种原型升级

以下是行为提案，伤害倍率、经验阈值、散射角度和数值曲线在原型试玩后确定。首四种战斗升级各最多两级，后两种辅助升级各最多一级；升级等级只在本局有效。

| 升级 | 前置条件 | 改变的行为 | 必须保留的约束 |
| --- | --- | --- | --- |
| 散射弹丸 | 携带主枪械 | 增加有限的侧向弹道，擅长处理接近的敌群 | 每次开火按基础武器消耗弹药并进入冷却；子弹数与整次攻击总伤害有上限 |
| 贯穿弹丸 | 携带主枪械 | 弹道可继续命中后方有限数量的敌人，奖励排成一线的站位 | 建筑和地形仍阻挡；同一弹道对同一敌人只结算一次 |
| 扫把广角 | 装备扫把 | 扩大近战横扫范围，第二级进一步强化清路能力 | 保留原生攻击输入、共享工具冷却、遮挡和安全击退 |
| 雨伞连刺 | 装备雨伞 | 一次合法触发形成短连刺，适合集中处理精英 | 连刺由宿主生成且次数有限；整段共享冷却，重复输入不重启序列 |
| 吸附拾取 | 当前活动支持经验拾取 | 扩大个人拾取半径，减少贴近敌群捡经验的压力 | 检查距离、通路和掉落归属；不吸取任务物资或替代长按救援 |
| 急救补给 | 本局首次选取 | 立即恢复部分生命，并提高后续任务补给的个人恢复效果 | 恢复不超过生命上限；不自动复活，满血时即刻恢复部分为零 |

急救补给的后续增益仍可使满血玩家受益，选项说明必须展示这一点。扫把和雨伞只能抽到当前装备对应的升级；主枪械两种升级可组合，效果次序和伤害上限由固定规则定义。

## 武器组合与后续进化

首个原型的组合来自主枪械、所选近战和辅助升级共同作用，玩家仍主动瞄准和选择近战时机。每个组合至少有一个需要站位或工具选择的优势，同时保留换弹、冷却和任务交互的压力。

| 组合方向 | 使用方式 | 代价或短板 |
| --- | --- | --- |
| 散射弹丸 + 扫把广角 | 先横扫击退，再用近距离散射清理敌群 | 需要靠近，远处目标仍难处理；换弹时依赖近战掩护 |
| 贯穿弹丸 + 雨伞连刺 | 沿街道把敌人引成队列，用贯穿清线，再集中刺击精英 | 依赖路线与站位，侧面包围时需要及时转移 |
| 散射弹丸 + 贯穿弹丸 | 在多个有限弹道上产生排队命中，形成枪械重点组合 | 弹药和子弹／命中上限仍约束输出，不能无限派生弹道 |
| 吸附拾取 + 急救补给 | 边移动边积累经验，在任务补给处恢复，减少冒险拾取 | 占用有限选择机会，直接伤害成长较少 |

效果按“基础武器 → 散射弹道数与方向 → 每条弹道的贯穿 → 唯一命中结算”处理。子弹不会因命中再次递归散射，额外击中仍检查建筑遮挡；角色切工具、换座或倒地不能刷新冷却、取消弹药消耗或重复播放攻击。

后续可以加入一件自动辅助装备槽，尝试环绕锅盖、便携喇叭声波等生活用品进化。环绕锅盖是有限次数的防护／推开效果，喇叭是有冷却的声波击退；不能默认无敌或隔墙伤害。自动辅助按姿态声明是否允许触发，司机、倒地、菜单和终局状态都必须停止攻击。

车载喇叭首期只承担集合与情境信号。车载攻击、更多同时武器、平底锅进化及武器转换在后续分别定义，完成手机可读性和预算验收后再增加。第一人称武器显示不遮挡道路、敌人和交互目标；自动辅助装备的效果不要求额外常驻第一人称模型。

## 骑行、步行与后座分工

| 状态 | 核心职责 | 可用行为 | 需要其他状态完成的事 |
| --- | --- | --- | --- |
| 司机 | 找路、转移、避开包围、选择停车位置 | 驾驶、观察、标记、集合信号 | 枪械和近战、经验拾取、物资领取与救援需停车下车或交给队友 |
| 步行 | 搜刮、清路、控制敌人、完成交互 | 枪械、近战、经验拾取、物资和救援长按 | 快速转移需要可用电驴；幸存者可步行跟随，乘车时需要空后座 |
| 后座 | 移动射击、掩护司机、观察和标记 | 使用主枪械、瞄准、换弹、保持本局枪械升级 | 近战、经验拾取、搜刮与救援需要下车；司机位不允许同时开火 |

首期经验拾取只由步行角色触发；后座击倒敌人可以产生掉落，但仍需停车后由步行成员拾取。合作共享经验使司机不会因驾驶职责落后。所有姿态保留已选升级，只有当前姿态允许的效果才生效；换座不会生成第二份装备或重置升级。

单人玩家负责驾驶和步战的切换：找到安全停车位，下车清路、领取物资，带幸存者上空后座再撤离。双人可以司机转移、后座掩护，停车后一起清路，其中一人下车救援。四人可分乘两辆车，并在救援点保留至少一个接应位置；分工随局势变化，不强制固定职业。

骑行阶段强调通路和安全停车，步战阶段强调范围、遮挡和武器组合。敌人压力与任务目标安排在不同停靠点，持续绕圈逃跑不会自动完成物资或救援；生存时长本身不是胜利条件。车辆耐久、上下车距离与安全下车检查继续复用宿主规则，升级首期不修改碰撞、车速、刹车或驾驶物理。

## 敌人、波次与可读性

| 敌人方向 | 战术作用 | 设计约束 |
| --- | --- | --- |
| 普通感染者 | 缓慢接近与包围，提供清路和范围武器的价值 | 保留可识别攻击前摇与安全击退 |
| 冲刺型 | 逼迫短时走位，增加停车位置和后座掩护的价值 | 冲刺有明显预警与恢复间隔，不突然从近处视野内出现 |
| 精英型 | 在救援点验证集中输出和组合选择 | 具备可辨认行为与有限耐久，不能只堆血量拖延撤离 |
| 远程型（后续） | 迫使玩家接近、绕行或使用建筑遮挡 | 独立验证弹道、遮挡、预警与手机屏幕可读性 |

刷怪沿共享路网选择可达入口，检查所有玩家的观察范围、安全距离、完整敌人身体和生成上限。找不到安全且可达位置就延后，不能把敌人塞入墙内或为满足波次瞬移到玩家旁边。当前波次完成后不会在补给选择阶段继续制造战斗。

压力来自敌人种类、接近方向和任务路线的组合；每阶段有明确活跃数量、总生成量、掉落、弹道及特效上限。重复消灭敌人受阶段经验总量与生成数量约束，不能通过无限刷新获得无限成长。后续数值需要同时考虑单人转移与多人分散视野，不能只测静止清怪。

第一人称、第三人称和既有可用视角需共用命中规则；更换镜头不改变伤害或允许穿墙。屏幕反馈区分经验、升级、受伤和任务目标，避免升级特效盖住敌人预警。手机自动辅助瞄准若加入，应作为明确的输入辅助另行设计和验收，第一版不默认新增自动主武器开火。

## 对局状态、合作与结果

本局保存有限的经验等级、待选机会、装备／升级等级、随机种子、当前任务阶段与已结算事件序号。这些状态归统一战斗宿主管理，升级后的属性只在本局生效；胜利、失败、退出或重新开局时释放临时效果，并从全新本局状态开始。

首期不支持中途读档、断线重入或房主迁移。可以记录已完成对局的结果摘要用于比较组合；记录按对局 ID 只结算一次，不能产生云币、购买权益或官方配送奖励。回到自由探索时恢复进入前的街区状态，活动中的车辆与物资不写入普通探索存档。永久解锁、正式排行榜与跨设备进度另行设计。

合作扩展先沿用现有房间生命周期：开始后不接收新成员，普通成员离队后更新集合要求，房主退出或失联结束本局。生命、弹药、任务阶段、经验分发、抽取、升级和命中全部由权威端确认；客户端提交操作意图或已提供的选项 ID，不提交经验、升级等级、击杀或伤害结果。

合作当前队员全部倒地时本局失败；最后一名仍可行动的队员离队、只剩倒地成员时也失败。补给阶段开启前，倒地成员须按既有救援规则救起，离队成员移出集合要求；不能停在等待升级状态中代替救援或拖延终局。

两类冷却与计时必须区分：战斗／任务计时可随全队补给阶段冻结；选择倒计时继续推进。成员在补给中离队时撤销其未完成选择等待，已经领取的队伍经验不回滚；仍在战斗时成员打开个人菜单，只释放自身输入。玩家倒地期间不自动攻击，也不能通过三选一恢复为站立；救援仍按既有实际交互执行。

生存规则、升级目录和抽取算法需有独立版本与内容 hash，合作各端必须一致。加入新状态后需要同步协议、宿主与客户端并独立验收，不能因本地原型可玩就宣称生产云端或 Steam 多设备已开放。

## 与 AI 自定义玩法的关系

先由原生规则验证生存玩法，再考虑作为 [AI 玩法包](ai-gameplay.md) 的后续战斗模板。AI 可以组合已发布的路线、波次模板、升级池、种子、时限和撤离条件；地图、武器、敌人和升级均使用受支持的稳定 ID。

升级目录需声明等级上限、前置条件、适用姿态、互斥／组合语义与预算。AI 不能提交任意伤害公式、派生脚本、未知武器、无限刷怪或官方奖励。模板依赖固定地图／宿主规则／升级目录身份，统一校验和合作权威规则不因 AI 创作改变。

本方案不扩大 AI 玩法包第一版的配送、探索和对白范围；战斗模板仍属于 AI 路线图的 P3 后续能力，原生玩法验收与开放接口验收分别记录。实时 AI 导演不是原型或离线游玩的必要依赖。

## 分阶段路线图与验收

各阶段均待实现，具体状态见 [后续路线图](roadmap.md#zombie-survival)，不承诺发布日期。

| 阶段 | 交付范围 | 验收条件 |
| --- | --- | --- |
| S0：规则与试验参数 | 固定街区与路线、三种基础武器、六种升级、经验／抽取和组合语义 | 正常任务流程保证五次选择机会；不可用／满级选项、替代补给、组合上限和姿态限制可解释 |
| S1：单人生存原型 | 十分钟短局、升级、骑行转移、清路救援与撤离 | 完整胜负可复现，至少两种组合有实际用途；选择不抢战斗输入，重复输入不重复升级，退出恢复原街区 |
| S2：合作与输入验收 | 共享经验、个人抽取、全队补给阶段、双座与救援分工 | 司机不落后，枪械／近战姿态合法，选择超时与成员退出无死锁；键鼠、触屏、手柄及真实联机分别验收 |
| S3：内容与组合扩展 | 精英／远程组合、辅助装备与更多任务变体 | 升级能改变打法，各效果仍保留遮挡、冷却与上限；手机目标和预警可读，完整场景与发布预算通过 |
| S4：开放玩法包模板 | 受控波次、升级目录、路线与撤离契约 | AI 生成内容通过同一校验；固定版本可重复试玩，非法组合和越界参数被拒绝，官方状态保持隔离 |

S1 先用普通感染者走通循环，再逐项增加冲刺型和精英型，未完成的敌人覆盖必须在验收中保留。原型记录选择分布、升级取得时间、任务卡点、失败原因、弹药压力、救援完成率和不同组合的实际用法；胜率或击杀数不能单独证明玩法有趣。

实现时按范围运行类型检查、规则测试和现有相关 E2E；核对桌面与手机的目标遮挡、按住释放、焦点、手柄选择以及退出／重开清理。性能诊断和验收遵循 [游戏性能优化手册](game-performance-playbook.md) 与 [渲染性能记录](rendering-performance.md)，报告真实就绪时间、整帧长帧与设备范围，不放宽现有预算。未完成实机、多人或发布验收时明确记录，设计稿本身不完成任何实现项。

S0 仍需确定街区与救援点、经验阈值、六种升级的数值／权重、五次选择的任务发放安排，以及阶段时限与原有救援规则的衔接。合作升级的建议选择时长、异常断开边界和后续辅助装备触发姿态需在对应阶段定稿。本文明确流程与职责，后续调整参数应保留版本和试玩证据。
