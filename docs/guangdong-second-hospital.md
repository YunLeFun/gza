## 实现与体验

`hospitalArchitecture.ts` 保存三个对象的体量划分；`pazhouLandmarks.ts` 负责不透明窗带、白色竖向分隔、门诊大窗框与粉灰填充、屋顶设备体、红色院名、楼号和门诊／急诊文字。门诊大窗及雨篷放在中央北翼，临街楼降为五层，避免原先三个等高挤出块的效果。标牌、门口和设备体位置按照片／示意图估计，未实现医院室内或病人业务。

材质和标牌复用现有玻璃纹理与 1024 px 图集；外窗只画外侧面，构件静态合批。近距离立柱、窗檐、楼号和植物继续按 280 / 320 m 距离裁剪，小构件不投射阴影，细节不参与水面捕获，没有逐窗灯源、远程瓦片或照片贴图请求。昼夜只修改已有材质发光。

城市游览新增「广东省第二人民医院」，镜头从中央楼西北侧、高 48 m 看向院区，方便查看错层与门诊立面。该镜头不是实拍位置；正常骑行仍沿已有道路和前场。

## 验证

模型测试检查三栋 OSM 替换、中央凹院空腔、北／南楼与连接部分的世界坐标屋面高度、五层临街楼、外窗朝向、资源所有权、昼夜资源复用和原有 4,500 三角形医院上限。地面与地图测试继续检查道路、院落铺装和地图连接。

`e2e/hospital.spec.ts` 检查桌面与 390 px 手机的游览入口、日夜截图、热身后资源复用、西侧骑行通行及暂停后的缓存绘制预算；原有 `jianghai-interchange.spec.ts` 继续验证桥下医院侧道路。

本轮 29 项相关单测、应用类型检查、生产构建、体积预算、发布产物校验与 `git diff --check` 通过。桌面／手机医院用例和三个既有江海立交用例共 5 项通过；本机浏览器使用 Metal GPU，医院用例固定 720p / 30 fps。默认软件 WebGL 在本机完整桌面用例触及 120 秒超时，未把它记为通过。

医院建模完成、渲染优化前的暂停缓存帧采样如下，每个视角 12 帧：

| 视角 | 绘制调用 | 三角形 | 现有 300 / 90,000 门槛 |
| --- | ---: | ---: | --- |
| 桌面骑行（含骑手／座舱） | 337 | 64,524 | 该轮调用超限；此前一轮为 338 |
| 桌面步行 | 296 | 62,022 | 通过 |
| 手机骑行 | 218 | 54,480 | 通过 |
| 手机步行 | 172 | 51,698 | 通过 |

该轮仅在步行视角断言绘制上限，因此当时的用例通过不代表桌面骑行达标。后续通过分阶段采样定位并合批座舱和短跨桥护栏，桌面骑行降至约 234 次，手机约 177–182 次；医院用例现同时断言骑行与步行均低于原有 300 次／90,000 三角形门槛。护栏按格保守裁剪会略增可见三角形，医院几何与质量不变。运行中的水面捕获和 GPU 计时另行采样，设置、结果与局限见[渲染性能优化](rendering-performance.md)；尚未测实体手机。

建模完成时的发布检查结果：街区入口 315.2 KiB gzip / 350 KiB，街区 CSS 8.8 KiB / 16 KiB，完整资源 11.99 MiB / 20 MiB；后续优化的最终构建数值见上述性能文档。医院自身继续低于原有 4,500 三角形上限，未增加光源或透明渲染。

## 后续建筑参考流程

无需先安装 skill 就能检索和建模。本仓库每个地标先保存来源与判断，按以下顺序继续：

1. 明确具体院区／地址；先核对可用且经授权的街景参考。
2. 用 OSM 保持位置、轮廓、道路和米制距离；用卫星图看体量分区，核对平台坐标系。
3. 查找官网平面图、楼层索引、规划与建筑师资料，先读指北针与比例尺，再对应楼号。
4. 用同朝向实拍校准立面、入口、招牌和屋顶；将观察、推断、估计尺寸分别写清。遇到抓取失败，可通过浏览器查找页面实际图片，不能把搜索摘要当成已看过的照片。
5. 保留原始底图与来源；用合批和距离裁剪增加辨识度，再做模型几何回归、桌面／手机截图、通行和体积／绘制预算验收。

只有需要跨项目反复执行、固定资料目录或统一工具操作时，再把这套已验证流程沉淀为 skill；医院的具体参数和来源继续留在项目文档。
