## 地理数据

`public/maps/tower-center.json` 来自 [OpenStreetMap API 的中心窗口](https://api.openstreetmap.org/api/0.6/map?bbox=113.3085,23.104,113.326,23.1125)，WGS84 范围 `[113.3085, 23.104, 113.326, 23.1125]`，约 1.7 km²。API 返回相交道路的完整节点；导入器将完整道路和闭合楼栋保留在已有整体地图边界内，而非按窗口边界制造新节点。数据遵循 [ODbL / OSM 署名](https://www.openstreetmap.org/copyright)。

- 229 条地面道路：35 条新增、194 条刷新既有 ID；其中 31 条既有道路的节点序列发生变化。原始节点 ID 保留，不把邻近或交叉的几何线段自动接成路口。
- 1,077 个道路节点：66 个新增，36 个旧节点坐标刷新，最大的旧坐标偏差约 28.86 m。新旧地图共享节点采用新来源坐标，避免路口重复叠置。
- 62 个地上闭合建筑轮廓：9 个新增、53 个按当前来源刷新。既有轮廓和广州塔中心没有位移；缺失楼高仍由既有规则估计。
- 8 条旧地面片段被删除或不再导入；这些片段已不在新源中，或位于当前水域而没有可用地面跨越依据。窗口边缘之外未经确认的道路保留。

获取时间为 `2026-10-08T15:14:54.690Z`，保留要素的最后编辑时间为 `2026-10-06T16:44:36Z`。获取日不代表每个要素均于当天编辑。来源保存 URL、完整源文件 SHA-256 和 1,368 个要素的 ID、版本与编辑时间，不携带贡献者账号资料。

`withTowerCenter` 在客村、滨江与琶洲原始数据合并后、程序建模和桥梁 / 立交增强前应用。河岸、水域、桥梁路径、现有短渠桥的跨水通行属性和专用高架层级保留。`access`、`bicycle`、单向标签沿用原始来源；楼层属性不会从无关的 `level` 标签推断。源中孤立的花园小路仍保持孤立，不新增无来源的导航捷径。

从保存的原始响应重建：

```sh
node scripts/import-tower-center-map.mjs /tmp/dayun-tower-center-osm
```

获取新来源并重建：

```sh
node scripts/import-tower-center-map.mjs --fetch /tmp/dayun-tower-center-osm
```

未来来源更新可能改变结果；本次离线重建与仓库内 196,812 字节 JSON 完全一致。

## 街道与广场

园区外的 `footway`、`path`、`pedestrian` 使用石铺，取消额外 1.6 m 侧向铺装扩张；TIT 的既有砖铺和专属前场保留。路面渲染与骑行的表面查询共用布局，医院既有入口连接线在步道边缘保留少量重叠，避免露出草缝。

地面机动车道按道路类型、宽度、车道数和单向属性绘制标线。艺洲路既有单行三车道路段改为两条白色分车道虚线；双向道路保留黄色分隔线。路口、停止线区域、桥隧、园区和专属精修铺装留白。标线由表面布局一次规划，使用合批薄片几何单独绘制，沿用路口留白和虚线相位。地面分类贴图不再烘入标线，避免 20 cm 白线在 50 cm/像素的贴图中丢失宽度、变成模糊淡痕。标线属于规则化美术表达，未经逐段现场核对。

广州塔广场的 8 张长椅和原有 52 段曲线矮墙使用同一份米制布局生成模型和 Rapier 碰撞，矮墙按模型朝向旋转。与已映射公共道路、步道相交处裁出开口，模型和碰撞同时分段并留出骑手余量，观光入口保持开放。海心桥南岸导航入口改为真正的零高度桥头，避免将弯曲桥面的跨中当作南端。

## 验证与限制

11 个相关单测文件、64 项测试通过，覆盖来源与坐标、离线导入、道路单向和桥头连接、步道与医院入口铺装、路口标线留白、地面贴图、广场开口及模型资源。2 项浏览器专项使用 Chromium / Metal，验证新地图实际加载、艺洲路键盘骑行、广州塔与海心桥地图导航、320 × 568 布局，以及真实 Rapier 家具阻挡、观光入口和三条已映射广场通路。应用类型检查、生产构建、资源体积预算和发布产物校验通过，预算未调整。

当前首屏性能仍有未通过项。冷缓存、Fast 3G、4 倍 CPU 的手机仿真，默认浏览器测得 44.254 s；同样网络与 CPU 条件下使用 Chromium / Metal 测得 20.689 s，均超过既有 15 s 目标。Metal 样本地图约 4.045 s 就绪、街道布局约 7.818 s 完成、场景约 16.818 s 完成，成本主要仍在本地布局与场景准备。未做本轮改动前后的同环境控制实验，不能将该超限全部归因于新增中心片区；这些失败不列为通过，后续扩建前仍需继续优化加载、建模和首帧工作量。设备仿真与桌面 GPU 结果不代替手机真机验收。


## 地面清晰度修复（2026-10-09）

上一次将 20 cm 白线烘入 50 cm/像素的色图，单条线只有 0.4 像素覆盖；线性过滤后变宽、变淡。赛道的几何标线不受这项限制。街区现在将现有白黄标线生成为同一个顶点色薄片网格，不再写入地面色图或保留着色器残影；路面分类精度、铺装细节 atlas、边界抗锯齿和远处细节过滤保持原有配置。

几何在 128 m 空间格边界切段，通过动态索引只提交距离骑手 240 m 以内相交的格，白黄两色共一次绘制。只有可见格集合变化时上传索引，不逐帧生成几何。标线接收阴影，不投射阴影；道路节点和路口留白后的虚线相位沿累计距离连续。水域轮廓也参与标线裁剪，保留轮廓孔洞中的岛屿道路，避免白线跨越地面河面开孔悬浮。

`e2e/ground-clarity.spec.ts` 在真实 WebGL 材质下，以 256 × 256 像素观察 2 × 2 m 地面，使用现有 50 cm/像素密度。标准 Chromium 与 Chromium / Metal 均通过：20 cm 白线的实测半高宽由 57.8 cm 恢复到 20.3 cm，10%–90% 边缘过渡由 41.4 cm 缩至 0.78 cm；道路铺装边缘过渡为 1.56 cm。实景回归同时检查艺洲路骑行、实际标线一次提交、地图导航及广场物理通道。该像素测量只说明固定测试机位的清晰度，不代表所有距离或设备的帧率。

本轮 49 项相关单测、7 项 Chromium / Metal 浏览器检查和标准 Chromium 的 3 项清晰度检查通过，包含 4 个曾经有悬浮标线的实际水中点，以及医院桌面／手机既有 `<300 calls / <90,000 triangles` 预算。应用类型检查、完整生产构建、资源体积预算和 219 个发布文件校验通过，预算未调整。
