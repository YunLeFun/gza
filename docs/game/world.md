# 世界与广州

**GZA：暴力电驴**从一名广州电驴骑手的视角出发，把送餐、认路、看风景和夸张踢击放进同一座城市。GZA 是「广州行动（GuangZhou Action）」的缩写，「暴力电驴」是第一版副标题。

你可以在熟悉的街边停下来，听陈叔说几句话；也可以回到赛道，在车流中找准位置，一脚把大云汽车踹开。城市探索与短局街机挑战构成两种不同的节奏。

## 从客村到珠江，再到琶洲

第一批城市内容围绕**客村 / TIT、广州塔滨江和琶洲**展开，使用同一套街区地图与导航连接探索、配送和活动地点。

| 区域 | 当前体验 |
| --- | --- |
| 客村与 TIT | 骑行起点、园区巷道、骑手站、陈叔对白与园区午餐配送 |
| 新港中路与丽园一带 | 通勤起点、街边门店、配送路线和电动车检查 |
| 广州塔与珠江滨江 | 广州塔、海心桥、滨江道路、塔内游览和观景点 |
| 琶洲 | 延伸道路、腾讯广州大厦等地标与城市游览 |

广州内容从「自由骑行 · 广州城市地图」进入。比赛中的云港环线和随机赛道承担街机挑战，不等于广州街区的真实道路布局。

## 一座逐步建设的城市

首期规划以广州塔为中心，半径约 5 km。**规划范围与已经开放的街区不同**：目前道路、建筑和交互点尚未覆盖整个圆形区域。

地图范围概览和「小云重工 施工中…」围栏标出尚未开放的方向。当前骑行沿已建设、可通行的区域进行，扩建后会逐步增加道路连接与地点内容。

城市参考公开路网、建筑轮廓和影像资料制作。路口连通、街区关系和地标外形帮助玩家认识方向，建筑高度、立面、室内和部分通行细节采用游戏化近似。游戏中的地图与检查点用于游玩，不能当作现实导航或现场情况查询。

## 画面与气氛

城市使用低多边形体块、卡通人物和清晰的车辆轮廓，保留广州道路、滨江空间、地标与街边生活的辨识度。夸张的踢击、撞飞和变身道具属于街机喜剧表达。

菜单与 HUD 采用黑色半透明面板、方角、细分隔线和紧凑读数；路线、警示和状态提示用各自的语义色表达。画面里的生活空间与界面保持同一款游戏的风格。

### 时间与天气

街区支持手动选择时间、昼夜流转，以及晴朗、阴天、小雨和薄雾。开启「跟随本机时间」后，城市时钟使用你的设备时区；关闭后回到手动时间设置。

当前天气影响天空、光照、雾和雨的表现，不改变骑行抓地、配送奖励或巡逻规则，也没有接入现实天气。

### 骑行与游览

骑行用路面、桥梁、导航和停放载具组织探索。游览提供独立观景镜头，可以切换观景点、环顾并调整高度，适合慢慢看城市；游览期间原来的配送、骑行和塔内流程会冻结，返回后继续。

## 当前内容与后续方向

当前已有自由骑行、上下车与步行、配送与骑手登记、制服解锁、车库、陈叔对白、巡逻与检查、城市游览和单人街机比赛。详情见[人物与载具](/game/characters)和[玩法设定](/game/modes)。

后续方向是把现有系统串成更完整的城市任务线，增加有区别的任务、人物与店铺服务，再逐区补齐广州地图。更多城市、可自定义地图包和创意工坊属于后续计划，尚未作为当前可用内容提供。

## 平行世界与人物内心（规划） {#parallel-worlds}

2026-10-17，维护者提出让去往的平行世界与三位主角的内心故事关联：大云喜欢科幻，首个进入的平行世界为丧尸世界；第二主角喜欢漫画，后续考虑漫画风世界；阿榕怀旧，后续考虑怀旧岭南风世界。人物背景见 [Demo 人物设定](characters.md#demo-cast)。

首个丧尸世界属于 [Steam Demo v0.1](../steam-demo-v0.1.md) 的现实 / 丧尸双世界范围。漫画与怀旧岭南世界是长线候选，不加入当前 Demo 制作承诺；女主角对应一个世界，也不自动增加第三套可操作角色系统。

2026-10-18，维护者同意按讨论建议补充设计并先提交文档。本轮采用下列叙事与人物成长方向作为后续设计基线；漫画和怀旧岭南世界仍分阶段验证，关卡机制与剧情节点尚未实现。

### 采用的叙事设计基线

平行世界客观存在，人物的内心影响他们会抵达哪里、注意到什么；世界中保留超出人物认知、可带回现实核对的事实。世界起源、具体触发与限制继续完善。下表确定情感方向，行动与线索示例用于后续关卡稿，不表示场景已制作。

| 人物与世界 | 可探索的内心矛盾 | 世界中的行动与线索示例 |
| --- | --- | --- |
| 大云 · 丧尸广州 | 失业后的不确定、希望重新掌控局面；擅长推理，但计划仍可能失效 | 用科幻兴趣与分析经验识别异常规律，准备逃生；一次判断失败后与同伴协作，救助已经认识的街坊。身体生存与“自己是否仍有价值”的压力形成呼应 |
| 周远（小周）· 漫画风广州 | 希望像漫画主角一样靠自己闯出名堂；独立、求助与承担后果之间的矛盾 | 夸张动作、英雄式期待与现实后果发生碰撞；从独自出头的期待，到愿意接受帮助、保护或支持别人。关键区域探索分格、拟声字和漫画构图引导路线，具体机制须另验证 |
| 阿榕 · 怀旧岭南广州 | 对父亲与旧街坊的思念；希望找回熟悉的过去，却逐渐发现记忆和事实存在差异 | 对照照片、旧门牌、修车工单和手艺痕迹，寻找父亲的路线；熟悉的街巷中出现她记忆之外的生活细节，推动她重新认识父亲的选择 |

偏好提供进入世界的情绪入口，人物成长通过具体选择和后果发生。每个世界的关卡稿必须写清“生活中的愿望 → 世界中的目标 → 一次受挫判断 → 主动选择及后果 → 带回现实的发现”；场景风格与这些事件一起推进。

### 保持三人共同参与

三人共同经历各世界，每段有一位主角承担主要情感线，另外两人仍能提供帮助、提出异议和获得线索。丧尸世界提前留下阿榕父亲的痕迹，并让周远第一次出现与破界有关的反应；具体物证与触发事件在 Demo 节点稿中选定。

世界的危险、其他人物与关键物证具备持续后果，并保留超出三人认知的信息，作为父亲失踪与世界异常的悬念。剧情内往返保持已经提交的世界事实；退出或重试则恢复到明确检查点。人物的情绪变化不能任意清空危险、改写物证或重置其他人的经历。

### 丧尸广州的光照与现有游戏约束 {#infected-visual-baseline}

2026-10-20，维护者确认 B「湿冷夜街」为丧尸世界的调性参考，并明确要求按现有游戏及时间变化考虑光照。采用的核心是 **环境偏冷、活人据点偏暖、危险与可行路线清楚可辨**。B 是夜间参考画面；日夜与天气继续变化，世界风格不覆盖城市时钟，不把进入丧尸世界等同于强制夜间或下雨。

当前 Godot 工作区已具备以下接入基础，本轮为只读核对，不代表新世界参数或发行验收已完成：

| 现有职责 | 源码入口 | 后续设计约束 |
| --- | --- | --- |
| 时间与日夜循环 | `scripts/game/session.gd` 的 `settings.hour` / `settings.cycling`，设置页已有对应控件 | 沿用一个权威时钟；切换世界不另建循环、不因风格预设改写时间或循环偏好 |
| 城市光照与天气 | `scripts/world/city.gd` 的 `_update_environment` | 已按时间更新主光方向 / 光色 / 能量、环境光、车灯、雾和夜景权重；天气控制雨粒子与雾，减少动态效果会关闭雨粒子 |
| 流式美术与夜景材质 | `scripts/main.gd` 的 `update_art_themes`、`scripts/world/art-themes.gd` 与 `gza_night` | 沿用日间 / 黄昏 / 夜间材质插值；新增世界偏移须考虑共享材质、后续载入单元及回到现实后的恢复 |
| 角色和画面风格 | 当前角色造型配置与原生设置入口 | 继续使用游戏已有方块人物、可选低多边形造型、地图、车辆和交互；世界氛围不擅自改写玩家造型及画面风格偏好 |

上述路径均相对于源码仓库 `apps/dayun-kicker-godot/`。后续扩展以“现有时间 / 天气求值 → 当前世界的光色与场景状态 → 现有材质和呈现”组织；世界参数是待接入的增量，不把预设设计描述为现有代码已支持。

| 时段 | 丧尸世界的目标表达 |
| --- | --- |
| 白天 | 保留正常日照和道路可读性，环境填充略冷、局部色彩收敛；通过已有街景中的空寂、任务物件与感染者制造不安，白天不压成夜景 |
| 黄昏 | 保留时间驱动的天空 / 日照变化，逐渐加强冷色阴影与活人据点的暖光反差，过渡连续 |
| 夜间 | 接近 B 的冷蓝环境与少量暖色据点；沿用现有车灯、路灯和夜景材质，仍能识别中近景敌人、路边界与交互对象 |

晴、雨、雾分别沿用既有天气选择。当前已核对到雨粒子与雾，概念图中的整段湿路镜面反射不作为已具备能力；确需湿润材质时另做小范围验证，不先新增大面积实时反射、光源或雨天抓地规则。

基调先在 **当前游戏同一地点与镜头** 上验收：保持地图、人物、车辆、实际渲染比例及物理一致，比较现实 / 丧尸在白天、黄昏、夜间及晴 / 雨下的可读性，并检查手动调时、循环、暂停、减少动态效果、切回现实与跨单元载入。后续视觉确认优先使用这些实机画面；生成概念图只用于讨论冷暖关系与情绪，不要求复制其角色细节、街景密度、树冠或反射。

三张生成稿及提示词保存在源码工作区的忽略目录 `artifacts.local/zombie-world-concepts-2026-10-20/`，B 为已确认的气氛参考；A / C 仅保留为黄昏 / 白昼的讨论材料。图片未接入游戏或作为公开文档媒体发布，正式媒体继续遵守 COS 流程。

### 三个世界的任务设计方向

**丧尸广州 · Demo 先验证。** 日常配送先让玩家认识一个门口和一位街坊，进入异世界后再次经过同一点。大云通过订单、时间或导航异常形成判断，计划受到阻碍后与小周、阿榕协作，完成躲避 / 踢退与救助或护送任务。结尾带回一条与父亲旧工单或修补记号有关、能在现实核对的线索。首章只推进一个明确事实，父亲的生死、去向和世界起源继续留白。

**漫画风广州 · 后续局部原型。** 小周期待独自完成一次英雄式行动，任务中需要接受同伴帮助，才能把人或物安全带出。视觉从现有适度漫画渲染进一步走向可读的分格、拟声字和跨页构图；先用一段 3D 街道验证分格如何提示或连接通路。分格间移动与破界能力形成表达联系，机关可用性和规则须经原型实玩决定。

**怀旧岭南广州 · 后续局部原型。** 阿榕沿父亲的旧客、修车铺与照片路线追寻线索。玩家比较同一门牌、招牌或维修物件的前后差异，发现一项阿榕原先不知道的事实，决定下一步调查方向。她既能保留对旧街坊的情感，也逐渐理解照片之外的生活；父亲是否在此出现和世界对应年代另行定稿。

这些方向是任务稿的写作约束，不自动增加完整护送系统、自由拍照、动态图像识别或每个世界独立的物理系统。先使用已有交互、固定剧情照片、手写线索数据和少量局部场景变体。

### 实现与验收顺序 {#world-implementation}

1. **先完善文档与节点草稿。** 使用稳定人物 / 地点 / 线索标识描述任务前置、完成、失败与恢复；每个世界保留一条可验证的现实线索和三人各自的作用。
2. **Demo 只做现实 / 丧尸闭环。** 按 B0-03、V1-04 至 V1-08 推进；保留同一锚点的位置 / 朝向、剧情原子提交、角色和车辆状态与跨进程恢复。线索只由宿主验证后写入，观察、退出与重放不复制关键物品或重复结算。
3. **再做漫画世界小样。** Demo 核心出口通过后，复用一段街道和少量分格装置验证可读性、骑行 / 步行、固定镜头变化与角色切换；通过前不制作完整漫画城市。
4. **再做怀旧岭南街巷小样。** 冻结年代与资料来源，完成同一地点的照片对照、一个父亲线索和一次主动选择；先验证观察任务能否被玩家理解，再决定扩展范围。
5. **扩展前检查状态与代价。** 验证往返、退出、重试、物件 / 同伴状态、声音和减少动态效果；按既有门槛记录资源、实际画面和性能，明确新增资产工作量。设计采用不等于原型或发行验收已通过。

具体执行勾选只在 [游戏开发待办](../development-backlog.md)维护；本页保存设计约束与验收依据。

### 视觉与玩法建议

三个方向均保留 3D 城市基础、稳定地点与电驴 / 步行交互，先通过局部变体、光色、声音、任务与表现手段产生差别。漫画风可探索较强的分档明暗、轮廓和冲击图形；怀旧岭南风从旧街景、店招、工艺与声景建立年代感，摄影前后对照承担实际线索。

具体年代与街景资料需要另行确认，阿榕的个人记忆、父亲留下的影像与历史广州分别记录。漫画分格改变通路、不同世界物理规则或全场景重建均需独立玩法验证，不作为画风选择的默认附带工作。

### 后续待定

- 在既定客观世界基线上，人物如何影响入口与观察、由谁造成异常、触发的限制与代价；如何在任务中留下可验证证据。
- 大云喜欢哪些科幻主题，为什么首个丧尸世界会触及他当前最在意的事情。
- 周远偏爱的漫画类型、英雄想象与破界能力的关系；关键分格机关如何通过操作和恢复用例验证。
- 阿榕怀念的是自己经历的广州，还是通过父亲照片认识的旧城；父亲留下哪些可以跨世界核对的事实。
- 离开每个世界后，人物关系、关键物件与现实广州具体发生什么变化。

后续实现通过 [开发待办 P2-03](../development-backlog.md#long-term)继续评估；当前切片先验证现实与丧尸世界的剧情、恢复和玩法闭环。
