# 街区急救委托（首版）

基于 `ba9132f63380adb1d1ffb1c14512fd685a0838a4`，位于单人广州街区。城市合作僵尸模式不共享此背包/委托。本功能没有噪声引敌或新增死亡惩罚。

## 一趟流程

1. 在地图「活动」打开「骑手站急救委托」，导航骑手站，停稳接单。
2. 导航三个补给地点之一：便利补给点（水 ×2 / 3 秒）、医疗补给点（急救包 ×1 / 4 秒）、维修补给点（电池 ×1 / 3.5 秒）。这些是映射到现有建筑外侧的**虚构游戏补给点**，并非真实商户信息。
3. 骑车到附近，按 **F** 下车，步行到标记 3.2 米内停下。按 **E** 或「搜索补给」开始。地图面板会关闭，搜查时能看到街道。
4. 移动、暂停、开地图、失去图形上下文会取消读条；也可按 E 或「中止搜索」。再次开始重新计时，奖励固定不会重抽。
5. **I** 整理十格外卖箱。物品按现有堆叠规则入箱，配送货物仍占一格。空间不足不领取也不耗尽地点；整理后可重试。
6. 取得急救包后返站，点「返站交付」获得 **120 积分**，可用于既有补给/改装。急救包不可误用或丢弃。

## 边界与存档

- 第一版只有一次有限委托，无自动刷新或无限重复领取；已搜索地点在存档中保持搜空。完成后未搜索点也不继续发奖励。
- 接单、获得物品、交付与背包/地点状态一同保存。读档不恢复正在进行的计时；已领取物资和已搜空地点一起恢复。
- 委托积分单独记账，并加入现有可用余额，不反复叠加到旧配送记录。交付同时移除一个急救包并把委托标成已完成；重复操作不再奖励。
- 老存档没有该字段时从未接单状态开始；不改变既有配送、商店、死亡规则。
- 手动加载旧存档仍是游戏既有的整体回滚语义，不承诺云端反作弊或跨存档合并经济。保存失败会提示，应手动保存。
- E 保留地铁、九号门店、陈叔、影院具体交互优先；附近有效搜查优先于笼统的活动地图快捷入口。
- 自由探索键位现为 F 上下车、I 外卖箱、B 后视镜、V 第一 / 第三人称；比赛与城市合作保留各自操作映射。

## 体验与性能范围

初始背包只占三格，这一趟固定物资通常使占用升到四格，因此新玩家的第一趟是寻路/交互教学，不是强迫丢物资的生存经济。已有满箱存档会实际遇到容量限制。当前不以额外塞满背包或缩小容量制造难度。

点位仅在地图初始化时选择三个现有建筑外侧位置，检查地面道路连接、建筑/水域及实际碰撞体，并逐段核验骑手站到门口的去程与回程；图上连通但途中有实体障碍的点位会跳过并寻找安全替代。不为每栋楼创建实体。运行时只查询三个记录并复用两个标记网格。找不到全部安全点位时不允许接单。

验证包括确定性状态机、实际地图/碰撞点位、存档往返及类型/构建检查。真实 Rapier 回归使用实际海滨/交通设施、公交站碰撞、固定停放车辆与启动时刻公交快照，以不超过 0.5 米的步长走完三个补给点的往返路线，经过停车、下车、步行进出门口、重新上车和返站交付；交付后读档再次领取不会重复加分。浏览器实际游戏操作和帧率需单独试玩；CPU 单测不能代替流畅性证据，也未覆盖任意时刻移动公交、街头事件和玩家改变后的障碍布局。

## 可复现地图检查

运行 `pnpm test:map`：先用现有资源流程恢复并校验固定版本，再运行搜刮闭环、路口桥梁、南西主路线、建筑道路净空、缺失资源处理与同源文档缩略图检查。运行 `pnpm docs:build` 会从同一份合成地图重新生成文档和管理预览的数据；不复用旧缩略图，也不上传新资源。

这些检查证明指定路线和状态转移，没有证明 5 km 内所有支路都畅通，也没有证明第一次试玩一定需要 10–15 分钟或已经足够有趣。人工试玩仍需检查找路、提示易懂性、镜头、流畅度及节奏；其他桥隧、复杂地形和未覆盖支路继续单独验收。
