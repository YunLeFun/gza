| `packages/dayun-kicker-content` | 两端共用的配送目录、规则 JSON、类型与迁移范围 |
| `packages/dayun-kicker-physics` | Rust Rapier GDExtension；平台动态库与 target 缓存不进 Git |
| `scripts/godot` | 内容导出、工具链校验、构建、原生测试、包检查与工作树冻结 |

这里的“同构”指**同一内容源和行为契约**：地图原点与地点 ID、配送目录和数值规则、骑行 tuning、ADV.JS 对白及 UI token 共用。Three.js 和 Godot 分别实现渲染、UI 与运行时；GDScript 不直接执行 TypeScript，当前 Rust 扩展也没有同时替换 Web 的 Rapier WASM。

陈叔开场、登记 / 接单选项及成功文案从现有 ADV.JS schema 1 编译程序导出，宿主再次核对位置、停稳、登记与订单状态。当前只覆盖两项宿主操作；完整条件、分支及章节执行仍在 M2。不复制一份首章对白单独维护。

## 运行与后续顺序

固定工具链为 Node 24、pnpm 11.10.0、Godot 4.7.2 和 Rust 1.96.0。首次按源码仓库原生 README 恢复资源并构建扩展，运行：

```sh
pnpm godot:dev
pnpm godot:test
pnpm godot:test:rendered
pnpm godot:export:win
pnpm godot:export:mac
pnpm godot:verify windows
pnpm godot:freeze
```

在陈叔附近停稳按 E 登记，再次交谈接单。W / S 油门与倒车，A / D 转向，空格刹车，V 切视角，F5 保存，Esc 暂停；任务节点、骑行每五秒、失焦和正常关窗保存。Windows 分发保留 EXE、PCK、DLL 的相对位置。
