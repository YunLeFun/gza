# 琶洲自由骑行：地标模型与精度

这次扩展使用公开地图中的真实位置和米制距离，取代旧通勤模式的压缩路线。**目前仍未达到全场景 1:1 实景复刻**：公开轮廓和部分总高度有依据，医院高度、建筑立面、露台标高、入口位置与沿街小物仍有近似。不能把模型当作实测建筑模型或精确到门的地图。

## 与旧通勤模式的区别

- 新场景是 `district.html`，由 `kecun.json`、`riverside.json`、`pazhou.json` 组成；OSM 道路节点和建筑轮廓以 WGS84 原点 `[113.3196, 23.0995]` 投影到局部米制平面。
- `map.ts` 的 `projectCoordinate` 使用经纬差和原点纬度的余弦转换，保留街区距离尺度；没有沿路线压缩建筑间距。
- [旧通勤说明](./pazhou-commute.md) 对应赛道版 `commuteTrack` / `commuteScene`，其中的 3.4 km 设计节奏、压缩位置和旧楼高没有用于此次模型。
- OSM 是公开地图几何，不是本项目取得的专业测量结果。地图完整性、轮廓更新时间和坐标本身仍有误差；快照来源、查询范围与校验信息见 `public/maps/pazhou.json` 的 `source`。

## 城市前场与入口

`pazhouGround.ts` 为腾讯南北楼、欢聚和省二医建立独立的局部石铺前场。医院使用导入数据的实际院区 `sites` 边界；腾讯和欢聚从公开建筑轮廓向相邻道路边线展开局部前场，按道路所属街块裁剪，不将两地之间或 TIT 至腾讯之间整片铺平。建筑占地、道路通道和河道从铺装多边形中扣除，医院入口只用一条窄铺装连接到现有公共步道。

这些世界坐标同时交给地面 atlas 与 `surfaces.at`，铺装无需新增地面 draw call。城区图块沿用近处半米分类贴图、远处共享贴图；TIT 的局部补丁不会因远处广场扩大。固定步长的地面查询另用 32 m 网格索引查找局部铺装。

六处小花坛参考建筑师图片中石铺广场和低矮植栽的语言，**花坛位置及形状没有实测依据**。花坛石边高 0.28 m，灌木约 1.1 m；模型、地面草面与物理碰撞共用同一份布局，保留宽敞入口且不占真实道路。腾讯在鼎新路一侧及南侧增设低位名称导视；医院在北入口与新港中路西侧有低位名称牌。文字作为游戏导视近似，全部复用同一张标牌 atlas。

`pazhouGround.test.ts` 覆盖石铺前场、医院步道连接、保留路面与水岸、建筑占地扣除、花坛道路净距以及 TIT 原地面不变。

### 腾讯入口、长扶梯与平台细化

2026-10-07 按用户提供的建筑师官网实景图复核后，移除了原先封闭首层盒的表达，补入中央高挑空开口、两侧玻璃门厅、银白立柱和厚檐。根据用户进一步确认，正面入口为三排并列长扶梯，各有独立踏面、扶手和倾斜腹部；共用罩棚与上端平台随三排总宽调整，支柱位于梯组外侧。南北楼之间的原平直连桥也改为错层连接体，加入斜向玻璃体块及平台间双扶梯，保留底部道路净空。

四层空中平台保留米制总高和悬挑轮廓，增加银白边框、深蓝灰网格板底、局部玻璃围护和退后房体。珠江侧中间收窄为镂空峡谷，其内为上端较宽、靠外，下端较窄、向内倾斜的玻璃幕墙，配有跟随斜幕收分的侧向玻璃围护和细框；平台前方保留空腔。夜间板底使用程序纹理发光表达蓝色星点，没有逐颗创建灯具。参考照片没有随游戏分发。

这些构件属于**外观重建**：官网照片没有标注入口朝向、扶梯精确尺寸、峡谷宽度、斜幕角度或各个平台标高；游戏南侧入口布局、长度、升高及幕墙细部均为照片比例近似。没有将未知尺寸标作实测数据。入口和跨街扶梯为静态外观，未实现搭乘；建筑占地仍有碰撞，骑行路线保持在室外道路及前场。正式入口名称与导航点也尚未核实。

依据分别是官网 [入口正立面实景](https://www.jeannouvel.com/wp-content/uploads/2017/02/dsc5537.jpg)、[南北楼之间的跨街平台实景](https://www.jeannouvel.com/wp-content/uploads/2017/02/dsc5944.jpg)、[峡谷玻璃幕墙近景](https://www.jeannouvel.com/wp-content/uploads/2017/02/dsc0573-1600x1091.jpg) 及 [蓝色板底夜景](https://www.jeannouvel.com/wp-content/uploads/2017/02/dsc6057-1600x2400.jpg)。官网正文仍含设计阶段措辞，因此不能据其交通功能描述推断正面幕墙中存在外露梯管。用户另给的百度百科页面本次未能读取，没有引用其中未经核查的尺寸。

### 腾讯夜景灯光

2026-10-07 按用户补充的仰视夜景照片（原页面链接未提供）及上述官网夜景参考，强化四层悬挑板底的蓝色、青色星点，加入平台周边与北楼屋檐的青蓝灯带。办公翼各层窗沿和入口檐口使用较弱的暖白灯带，中央斜幕保留玻璃窗格发光。北楼屋檐下也补入蓝色星点。

星点采用固定种子的程序贴图，带有位置、亮度和颜色差异；不闪烁，不逐点创建灯具。青蓝、暖白及不发光区域共用一张三色发光 atlas，灯带面片与已有银灰金属构件合批，普通构件固定采样不发光区域。近距离窗沿随原有细节距离裁剪。白天星点和灯带不发光，傍晚减弱，夜间增强，接入现有地图时间与昼夜切换。没有增加点光源、透明泛光面片或阴影捕获次数；灯位、疏密和亮度是游戏外观近似，未采用照片作为贴图。

### 腾讯游览截图的辨识与限制

2026-10-07 根据用户提供的珠江对岸正面实景图（图上署名「知乎 @良有方」，原页面链接未提供），并对照官网[整体实景](https://www.jeannouvel.com/wp-content/uploads/2017/02/dsc5607-1600x2400.jpg)和峡谷近景，纠正正面中缝的表达。这里是镂空峡谷中的内凹倾斜玻璃幕墙。移除先前误建的三条外露封闭斜梯、相关梯管穿洞和接驳小平台；两侧办公翼扩大，中缝约占塔身宽度的 24%，两侧留空。用户随后指出倾斜方向，并补充高清正立面照片（原页面链接未提供）；斜幕已修正为上端较宽、靠外，下端较窄、退入楼内，同时调整侧面收边、框架和横向分格。上端宽度约为塔身的 24%，下端暂按上端的 72% 近似。真实入口三排扶梯、南北楼之间的跨街连接及双扶梯保留。

中缝比例、斜幕角度和幕墙分格仍按照片近似，模型不作为竣工 BIM。后续继续匹配同朝向实景，校准平台标高和悬挑深度，并细化空中村落小屋与植栽。

原腾讯观景位位于塔楼东北侧约 `(180, -300)` m、高 70 m。截图左下的横向通用楼块来自 OSM `845986509`（数据名称「阿里巴巴」，高度 57.5 m），更左侧的高楼来自 `845986507`（数据名称「阿里巴巴华南营运中心（南塔）」）。在当时截图中它们采用通用楼栋外观。现已按独立实景来源重建阿里南北楼，见[阿里建筑记录](alibaba-south-china.md)，不应继续将它们认作腾讯构件。截图右侧逐层露台塔楼为欢聚 `1396804443`。这些对象与腾讯南北楼使用不同的建筑 ID。

腾讯默认观景位调整为珠江侧约 `(40, -340)` m、高 32 m，观察南北两楼，减少邻楼与腾讯北楼的投影重叠。偏移以南楼真实轮廓中心为原点，使用游戏米制坐标；这是镜头调整，不改变地图建筑的实际占地。

## 实现与预算

2026-10-08 增加腾讯西侧鼎新路 / 美居北街的实拍参考路口及黄昏游览视角，补入草坪岛、黄色网格、过街设施和四向信号，并调整晚霞配色及分层云带。照片定位依据、近似范围和验证详见[腾讯路口与晚霞记录](tencent-junction-dusk.md)。

2026-10-07 根据用户允许适度放宽首屏体积的要求，将首页与街区入口的 JavaScript gzip 预算分别由 270 KiB 调整为 300 KiB，增加约 11.1% 余量。预算通过 Vite 构建清单统计入口与静态依赖，并合并 HTML 声明的 modulepreload。街区加载屏使用轻量 `bootstrap.ts` 后，其启动必需的动态 `main.ts` 及全部静态依赖仍计入同一 300 KiB 预算；随该模块加载的 CSS 也纳入原 16 KiB 预算，不能借动态入口绕过检查。清单或必需启动模块缺失会使检查失败。场景、Rapier 等其余动态分包保持原有延迟统计口径；音频、产物总量与绘制预算不变，移动端首次可玩 15 秒检查仍保留。这不是全部游戏资源大小或浏览器限制。

加载器本身另有 8 KiB gzip 的静态 JavaScript 上限，统计 HTML 预载与静态依赖，防止加载器再次提前拉取游戏运行时。Vite 的 `\0vite/preload-helper.js` 精确归入独立 `startup-helper` 分包，避免辅助函数随 `ride-core` 带入 Three.js；其他分包规则保持不变。

`createPazhouLandmarks(map, glazing?)` 返回 `root`、`shared`、`replacedBuildingIds`、`captureHidden`、`update(point)`、`setTheme(theme)`、`dispose()`。当前替换地图中实际存在的十七个已识别建筑 ID，不以附近无名楼代替目标地标。阿里模型与区域细节裁剪见[单独记录](alibaba-south-china.md)，新总部的原始资料、高度精度和验证见[逐栋索引](pazhou-internet-headquarters.md)。

主体和近距离栏杆、树冠、细窗檐分别静态合批。细节在距轮廓边界约 280 m 内开启，超过 320 m 隐藏；没有双份完整模型。腾讯南塔、欢聚保留到约 3.1 km，北楼约 2.4 km，医院约 1.35 km。小米、唯品会、国美、TCL 各自的小范围园区合批主体与细节，以逐栋边界判断园区可见性。外层场景不要把整个地标模块合并，否则会丢失局部裁剪。

材质使用已有的共享不透明玻璃纹理，昼夜只修改发光强度；没有逐窗光源、透明排序或额外透射渲染。医院贴墙窗带只保留外侧面片。

参考用户提供的珠江夜景照片（琶洲滨江步道、腾讯与阿里实景、广州大桥与探照灯；原页面链接未提供，照片未随游戏分发），统一调整夜间城市层次：

- **夜空与雾**：夜间天顶保持蓝色，地平线改为紫灰色城市光晕，远处楼体融入雾色。
- **总部媒体立面**：欢聚（蓝）、唯品会（粉）、TCL（红）、国美（紫）、阿里（冷白）在立面图集的楼板位置烘焙连续 LED 横线；小米保留克制的室内光，腾讯沿用板底星点。颜色是游戏近似，不代表各运营方的实际灯光秀。
- **通用楼体**：街区通用楼与外扩楼体共用一张小型窗格发光纹理，按时段调节强度；夜间墙体乘以 `SHELL_TINT` 压暗，使窗光与 LED 成为焦点。通用楼的砖格 UV 通过纹理变换映射到 2.4 m × 3.2 m 窗格，不改几何；外扩楼体增加一组 UV。
- **楼顶灯冠**：外扩区高于 90 m 的约三分之二楼体增加 LED 灯冠和红色航空障碍灯，随楼体常驻范围重建为单次绘制；白天隐藏。
- **探照灯**：欢聚与 TCL 西塔楼顶各三束叠加探照灯，交叉面片两侧渐黑，避免描边；减少动态效果偏好下停止摆动，白天隐藏。
- **广州大桥与滨江**：梁桥两侧桥面边缘增加品红 LED 线、桥墩盖梁下沿泛光与低位护栏灯（保持桥体低于 20 m 的剪影）；江岸护栏下增加暖色灯带，沿江岸累计每约 40 m 一盏球灯。只有桥面 LED 线与桥墩泛光进入水面反射层。
- **白天隐藏**：灯带、泛光、灯头与灯杆使用专用的夜景材质，白天整批隐藏，黄昏与夜间显示。`e2e/district.spec.ts` 海心桥江岸两处视角白天与 `main` 一致（76.5k / 85.5k 三角形），黄昏与夜间约 75–79k，低于 90k 上限。

上述灯效使用共享发光材质并入既有合批，没有新增点光源或阴影。新增绘制约为：外扩灯冠 1 次、探照灯 1 次、桥体与江岸各增加 1–2 种共享材质。本轮做了本机 WebGL / WebGPU 固定游览视角的画面检查与上述江岸三角形回归，没有测量帧时间；完整游戏资源 raw 预算超出约 2.6 KB 待确认。验收前需按[性能手册](game-performance-playbook.md)补测。

WebGPU 下总部立面原先共用一个 program cache key，节点图会绑定第一个材质的图集区域、色调与强度，导致所有总部显示同一种立面。现改为按立面样式区分 key；WebGL 仍共享一个程序。
