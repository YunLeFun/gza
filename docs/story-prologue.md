# 序章 · 最后一个工作日

《GZA：暴力电驴》的新剧情档从大云被裁员开始：冷开场演出 → 交还控制 → 徒步去客村骑手站 → 陈叔接待、登记、领装、领车 → 第一次发动 → 骑行教学 → 接回第一章的园区午餐（`tit-lunch`）。序章目前只在 Godot 完整游戏实现；Three.js Web 试玩继续从骑手站开始，不追平这段流程。

## 演出与玩法顺序

| 段落 | 画面与动作 | 状态 |
| --- | --- | --- |
| 冷开场 · 秩序 | 15:00，园区高层工位。键盘声和空调底噪，大云在打字；窗外是真实城市与广州塔。 | `layoff` |
| 通知 | 日程弹窗与人力资源部视频会议。声音只出现在字幕里，没有第二个人物出镜。 | `layoff` |
| 撞击 | “岗位不再保留”落下时，手停在键盘上方，键声切断，环境声收窄成耳鸣。近景推到脸：想开口说“我……”又停住，肩膀塌下，右手攥拳后慢慢松开，屏幕变灰显示“账号已停用”。 | `layoff` |
| 离开 | 他从头顶摘下工牌放回桌上，起身拿背包。淡出后切到街边，城市声逐渐展开。 | `layoff` |
| 动机 | 手机震动，陈叔来消息：“站里正缺人手。先过来喝杯茶。”大云吸一口气，点头。 | `layoff` → `walk` |
| 交还控制 | 镜头升到肩后，接上可玩的跟随视角。目标为“去找陈叔”。 | `walk` |
| 徒步 | 玩家穿着办公衣服，背着背包走约 52 米（1.6 m/s 步行），沿蓝线到站。没有电驴，也不能改乘共享单车、公交或出租车。 | `walk` |
| 接待 | 陈叔端茶招呼。大云说想试试。登记工号 0817。 | 登记 |
| 领装 | 大云从装备架上拿起工衣，切到陈叔近景时换好工衣。再拿头盔，戴上，扣扣带。 | 领装 |
| 领车 | 镜头切到电驴：车灯闪两下，解锁提示音响起，电驴从此绑定为大云的车。 | 领车 → `tutorial` |
| 第一次发动 | 玩家走到车旁按 F。左手握车把、右手扶座，上车；仪表亮起，响起启动和弦，镜头回到跟随位置。 | `mount` |
| 骑行教学 | 加速到 15 km/h → 骑行中拐一个弯 → 刹车停稳 → 沿蓝线到练习点停稳 → 回站按 E 接园区午餐 → 云拱门取餐 → TIT 北侧交付。 | `tutorial` → `done` |

整段冷开场约 33 秒，接待约 24 秒，第一次发动约 2.5 秒。骑行教学依据玩家的实际操作推进，不设时间限制。

## 状态与存档

序章进度属于会话本身，按 `prologue: {stage, gear, bike, step}` 存档，并参与存档校验；动画和镜头只负责表现。

- `stage`：`pending`（尚未选择的新档，即原有章节起点）、`layoff`、`walk`、`tutorial`、`done`。
- 领车前没有玩家车辆：不绘制骑手电驴，也不生成停车碰撞体，不能上车或改乘其他交通工具。领车后，骑手站车位上只有一辆玩家电驴。
- 登记、领装、领车在各自镜头的同一节点提交，三者都是幂等操作。重复对话、读档、跳过或重新进站都不会重复发放。
- 中断恢复：冷开场中退出，会从冷开场开头重播；接待中途退出，读档后已提交的项目保留，再按 E 从下一项继续；骑行教学保留当前步骤。
- 旧存档没有 `prologue` 字段时视为 `done`，原有车辆、装备、订单和章节进度不变。旧的原生 M1 午餐切片导入时也按已完成处理。
- 互相矛盾的状态会被存档校验拒绝，例如“教学中却没有车”“步行阶段却在骑车”或“未领车却已接单”。

## 跳过、暂停与输入

- 演出期间按住空格或手柄 A 0.8 秒即可跳过；Esc 打开的暂停菜单里也有“跳过演出”。跳过会按顺序补齐尚未执行的提交，自然播放与跳过最终进入同一个有效状态。
- 演出结束或跳过后，不会残留演出镜头、遮幅、字幕、手机卡片、环境声收窄、道具或输入锁。仍按住的方向键需先松开，才能重新生效。
- 菜单、失焦和暂停会冻结演出时钟。演出期间只响应菜单键和跳过。
- 开启“减少动态效果”时，故事信息完整保留，推镜、摇镜和过渡混合改为直接切换。
- 步行改为相对镜头方向操作，镜头随角色朝向缓慢跟随，并且不会穿过静态碰撞体。

## 声音

序章没有配音和音素素材。对白只用字幕表达，不声称口型同步。环境声复用现有的城市循环；办公室底噪、键盘、提示音、视频会议接通音、耳鸣、心跳、锁屏、手机震动、解锁、启动和弦、头盔扣扣、登记盖章等效果均为程序合成，不新增媒体文件。办公室和撞击时刻的环境声收窄由低通滤波和音量变化实现。

## 新档入口

欢迎页对新档提供三个入口：“开始新故事 · 序章”“跳过序章 · 从骑手站开始第一章”（原有起点，需要找陈叔登记）和“自由骑行”。在序章中途改为自由骑行时，未完成的交接会一次性补齐。

## 实现位置

- 共享内容：`dayun-kicker/packages/dayun-kicker-content/data/prologue.json` 保存台词、提示、规则阈值和教学步骤。`scripts/godot/prepare.ts` 在真实道路图上规划步行起点和练习点。
- 程序美术：`apps/dayun-kicker/src/render/dayunModel.ts`、`dayunAnimation.ts`（大云和 16 组烘焙动作）以及 `prologueSetModel.ts`（办公室、装备架、道具），通过 `pnpm godot:art` 导出 GLB。
- Godot：`scripts/game/prologue.gd`（持久状态）、`scripts/world/prologue_director.gd`（镜头、调度、字幕和声音）、`scripts/world/dayun_animation.gd`（大云的动作与装束）。宿主接线在 `main.gd`、`city.gd` 和 `hud.gd`。
- 陈叔的站内问候按是否已登记分为两句：已登记时不再自我介绍。这两句都在 `zhou-hai-re.json` 中修改，并通过 `pnpm story:build` 生成。

## 验证与限制

`tests/prologue-contracts.gd` 检查状态转换、跳过与自然播放的一致性、领物幂等、中断恢复、旧档兼容和非法状态。`tests/dayun-animation.gd` 检查动作、步态速度、手部接触和装束。`pnpm godot:test:prologue` 在实际渲染的宿主中通过 InputMap 自动完成全流程并保存关键帧；它属于自动化渲染证据，不等同于人工完整游玩。

步行、演出和骑行用同一个大云模型：一套骨架、四肢连续蒙皮。大云和陈叔默认跟随世界造型（广州为方块），设置里的「角色造型」可改选方块、低多边形或厚涂卡通；陈叔没有厚涂卡通造型时回退到方块。大云的两种造型共用骨架、动作和接触点；陈叔的方块版建在同一套共享骨架上，动作名与旧模型一致。序章流程不受影响。玩家电驴按接近真实的比例缩小显示（约 0.86 倍），车上原有的块状骑手留给 NPC 使用。骑行时由 Godot 自带的 TwoBoneIK3D 把双手和双脚贴到电驴导出的插槽上，停车时左脚落地。第一次发动的镜头从正面拍大云本人握把上车。角色与骑行的细节见 dayun-kicker 仓库的 `docs/dayun-character.md`。
