# 游戏开发待办

更新日期：2026-10-20。**执行待办统一维护在 `gza/docs/development-backlog.md`；游戏代码、测试与构建继续在 `dayun-kicker`。** 源码仓库只留文档入口，不复制第二份清单。

当前目标是 Godot 离线单人 Steam Demo：先验证 10–15 分钟垂直切片，再扩展到双主角、双世界、五幕与 45–60 分钟完整体验。美术暂定为低多边形 3D、克制漫画表达与广州街坊暖色；Demo 阶段剧情人物先用类 Minecraft 的方块造型打通技术流程（共享骨架、动作烘焙、挂点、导出与造型切换），低多边形人物作为可选造型保留。之后按世界切换造型；AI 生成能力足够或有美术资源时，再按同一骨架契约替换为精细模型。产品取舍、剧情原案与相对排期见 [Demo 设计计划](steam-demo-v0.1.md)；历史功能与长期方向见 [路线图](roadmap.md)。

人物与世界设计已按维护者意见整理为后续基线：大云、周远（小周）、阿榕共同经历客观平行世界，分别承担丧尸、漫画风与怀旧岭南方向的主要情感线。约束和机制验证顺序见 [世界设计](game/world.md#world-implementation)。2026-10-20 确认 Demo 分为现实广州的第一章与丧尸平行世界的第二章，《粥还热》拆分复用，见 [Demo 两章剧情设计](story-demo-chapters.md)。当前只提交设计；以下实现任务仍按验收证据勾选，漫画与怀旧岭南原型列入 P2。

## 维护规则

- 任务 ID 稳定保留，拆分时新增 ID 并关联旧项；P0 表示 Demo 必须完成，不表示所有 P0 同时开工。
- `[ ]` 表示该项交付尚未验收关闭，包括已有部分实现但仍需补齐 / 验证的情况；`[x]` 只用于交付与验收证据都齐全的任务。
- 现有驾驶、配送、剧情和存档按复用与增量处理；不因出现在待办中就重做系统。当前依据是只读初盘，未完成完整运行审计。
- 开工后在对应任务下追加负责人、阻塞项、关联 Issue / PR、验收版本与结果；不凭规划文字或一次构建成功勾选功能。
- 后续若建立 GitHub Issues，优先在 `gza` 以同一任务 ID 跟踪项目工作，关联 `dayun-kicker` 的实现 PR。含私有源码或原始诊断的问题可留在私有仓库，公开清单只保留可公开的摘要与结果；不重复维护另一份任务正文。
- 原始日志、截图、trace 与构建包留在忽略目录或既有制品渠道；公开文档记录方法、结果和限制。新媒体沿用 [COS 资源流程](media-assets.md)。

## V1 · 10–15 分钟垂直切片（P0） {#vertical-slice}

- [ ] **V1-01 复用并打磨首次配送。** 依赖 B0-03 / B0-04；开场操控大云，从失业后的简短引入到陈叔处注册成为外卖员，再通过取餐、骑行导航与停稳交付完成一单；背景在行动中逐渐揭露，无需外部教程，超时与失败后果可理解，暂停 / 对话不误推进计时。
- [ ] **V1-02 完成一段 3D 美术样板。** 依赖 B0-04；以现有地图、人物造型、车辆和光照系统为基础，按 [已确认的丧尸世界基线](game/world.md#infected-visual-baseline)设置冷环境 / 暖色据点；保留时间与天气驱动，检查白天 / 黄昏 / 夜间、晴 / 雨、调时 / 暂停 / 减少动态效果、切回现实及跨单元载入的路线与敌人辨识。交付当前游戏的固定机位对照，不复制生成图的模型、密度或湿路反射；性能验收见 R3-02。
- [ ] **V1-03 实现一次剧情驱动的换角。** 依赖 B0-03、V1-01；两主角共用基础控制，各完成一次有意义的操作；切换后输入、相机、角色 / 车辆位置和任务一致，未受控角色不会因掉队卡住流程。
- [ ] **V1-04 接入异常订单与线索任务。** 依赖 B0-03、V1-01；沿用共享 JSON 和现有宿主校验，新 Demo 使用独立内容 ID；异常线索引向锚点，并为父亲线索与小周的破界前兆各保留一次可观察事件。物证须可带回现实核对，重复交互不越级、不复制关键物品或重复结算，旧章候选仍可运行。
- [ ] **V1-05 实现最小双世界切换。** 依赖 B0-03 / B0-04、V1-04；共享地图基础，切换必要场景变体、敌人、碰撞与任务；锚点位置 / 朝向一致，加载失败可恢复源世界，重复触发不产生半提交状态。
- [ ] **V1-06 验证一种感染者与基础近战 / 躲避。** 依赖 V1-05；复用章节遭遇基础，补足短关卡实际需要的感知、追击和脱困；战斗或绕行均能到达安全点，敌人卡住不阻断任务。
- [ ] **V1-07 保存并恢复角色与世界状态。** 依赖 V1-03 / V1-05 / V1-06；扩展现有版本化存档，覆盖切换前、提交后、遭遇与安全点的跨进程恢复；中途退出回到最近提交检查点，旧档不被错误覆盖。
- [ ] **V1-08 验收完整切片。** 依赖 V1-01 至 V1-07、B0-05；新档连续实玩约 10–15 分钟，含换角、异常、切世界、最小遭遇与重试；收集新玩家时间、迷路点和规则理解，列缺陷后决定是否扩展，自动测试不替代人工实玩。

## 完成记录格式

在任务原位置追加简短记录，例如：

```text
状态：待开始 / 进行中 / 待验收 / 阻塞 / 已完成
负责人：实际执行者；未确定时写待分配
关联：Issue、实现 PR；未创建时留空
依赖 / 阻塞：尚未满足的任务 ID 或外部条件
验收：源码 / 内容 / 构建版本，运行环境，结果与未覆盖项
证据：可公开汇总链接；私有原始证据仅记录其受控位置
```

当前仅建立本地清单，未创建远程 Issues、分配人员或承诺日期。设计问题继续在 [Demo 计划的待明确问题](steam-demo-v0.1.md#_10-后续待明确的问题)中收敛；影响实现的规则在对应任务开工前确定。
